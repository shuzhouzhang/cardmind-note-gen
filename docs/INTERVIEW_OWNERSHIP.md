# CardMind 项目掌握与面试过关手册

这份手册不要求记住整个仓库。目标是让你能够诚实地说明上游基础、CardMind 改造、设计取舍和验证证据，并能在追问下沿真实代码继续讲。

## 1. 面试时的真实项目边界

推荐开场：

> CardMind 是我基于开源 NoteGen 二次开发的本地优先知识学习桌面应用。我保留了编辑器、Tauri 桌面能力和 Agent 基础，在此之上聚焦对话导入、知识卡片、知识图谱、复习和结构化知识摄取。项目当前最大的工程问题是两条知识处理路径还没有完全统一。

不要使用以下说法：

- “整个项目都是我从零写的。”
- “这是完整的多 Agent 系统。”
- “Memory、Skill、MCP 已经全部投入使用。”
- “前端图谱已经完全由 `cm_knowledge_edges` 驱动。”
- “已经在大规模用户数据上证明了性能和准确率。”

### 需补证：代码存在，但还不能用于强结论

- 当前 CardMind 源码的全量 Windows 桌面重建和安装验证。
- 用真实个人数据完整执行一次 `ingest -> pending -> apply -> status`。
- 两条知识路径统一后的迁移和兼容性验证。
- 卡片生成准确率、耗时、成本等可复现实验。
- 将当前大工作区改动拆成来源清晰、主题单一的 Git 提交。

### 暂时不能写进简历

- 多 Agent 调度、分布式任务执行或云端高并发。
- 已启用的长期记忆、Skill 或 MCP 生态。
- 未测量的准确率、性能提升或用户规模。
- 无法从提交、代码、测试或运行记录对应到的个人贡献。

## 3. 五级掌握标准

每个模块使用同一把尺子：

1. **定位**：知道入口文件和用途。
2. **画图**：能画出输入、输出、依赖和数据存储。
3. **追踪**：能沿一次真实请求说明每一步状态变化。
4. **取舍**：能解释为什么这样设计、替代方案和代价。
5. **改动**：能独立修改、测试、演示并形成提交。

架构、Agent 和知识数据链路至少达到第 4 级。准备作为个人亮点讲的功能必须达到第 5 级。

## 4. 模块过关标准

### 4.1 整体架构：目标等级 4

不看文档，画出以下结构：

```text
用户
  -> React / Next.js 页面
  -> Zustand 业务状态
  -> Agent 或卡片生成
  -> Tauri 原生能力
  -> SQLite / Markdown / store.json
```

必须能回答：

- React、Tauri 和 SQLite 的边界分别是什么？
- 哪些数据进入 SQLite，哪些进入 Markdown 或 `store.json`？
- 为什么这个应用适合 local-first？
- 为什么保留桌面壳，而不是只做浏览器页面？
- 应用启动失败时从哪一层开始排查？

通过证据：五分钟内默画完成，并连续讲两遍没有结构性遗漏。

### 4.2 Agent 主链路：目标等级 4

核心路线：

```text
chat-send.tsx
  -> AgentHandler.execute
  -> AgentRuntime
  -> 上下文压缩与提示词组装
  -> 模型流式响应
  -> tool_calls
  -> 权限判断
  -> 工具执行
  -> 工具结果回填
  -> 下一轮模型请求或结束
```

读代码时为一次真实请求填写：

| 节点 | 输入 | 输出 | 会修改什么状态 | 失败后怎么办 |
|---|---|---|---|---|
| `chat-send.tsx` |  |  |  |  |
| `AgentHandler` |  |  |  |  |
| `AgentRuntime` |  |  |  |  |
| `PermissionEngine` |  |  |  |  |
| `ToolRegistry` |  |  |  |  |

必须能回答：

- 普通聊天循环和 Agent 工具循环的本质区别是什么？
- 为什么限制最多 15 轮？达到上限后用户看到什么？
- 参数不完整、工具不存在、权限拒绝、工具执行失败分别如何处理？
- `ContextManager`、`PromptAssembler`、`RecoveryManager` 和 `TraceRecorder` 各解决什么问题？
- 为什么注册表里有 Memory、Skill、MCP 定义，活动工具却过滤了它们？

通过证据：在调试器里观察一轮 `messages -> tool_calls -> tool result -> messages`，保存一张调用链截图和一段自己的说明。

### 4.3 用户可见制卡：目标等级 5

核心路线：

```text
来源文本
  -> 分块并计算覆盖率
  -> 模型生成 JSON 卡片
  -> 解析和规范化
  -> knowledge_cards
  -> 图谱展示与复习调度
```

必须能回答：

- 为什么不能简单使用 `text.slice(0, N)`？
- 如何证明分块没有漏字或重复覆盖？
- 模型输出不是合法 JSON 时怎么办？
- `sourceType`、`sourceRef`、`sourceTitle`、`sourceSnippet` 分别解决什么问题？
- 复习记录为什么与卡片主体分表？

通过证据：运行三项分块测试；手工导入一段超长对话；从生成卡片追踪回来源文本。

### 4.4 结构化知识摄取：目标等级 4

使用临时数据库完成：

```text
python -B scripts/cardmind.py --db <临时路径> ingest <输入>
python -B scripts/cardmind.py --db <临时路径> pending
python -B scripts/cardmind.py --db <临时路径> apply <知识JSON>
python -B scripts/cardmind.py --db <临时路径> status
```

必须能回答：

- 原始消息、知识点、来源、关系边和运行记录分别存在哪里？
- 稳定消息 ID 和 `canonicalKey` 如何支持幂等？
- `sourceMessageIds` 为什么比仅保存摘要更可靠？
- `active`、`quarantine`、`archived` 有什么区别？
- UI 的 `knowledge_cards` 和结构化 `cm_*` 为什么会形成双模型？

通过证据：同一输入导入两次不重复；低置信度知识不进入活动图；任意知识点可以追踪到来源消息。

### 4.5 React、Next.js、Tauri：目标等级 2 到 3

达到以下程度即可：

- 能从一个按钮找到事件函数、store、数据库调用和结果展示。
- 能说明浏览器代码与 Rust 原生能力的边界。
- 能增加一个字段并完成数据库、TypeScript 类型、store、UI 的传递。
- 能判断问题属于渲染、状态、网络、Rust 还是数据库。

暂时不用研究每个样式、Tiptap 扩展、国际化文件和移动端实现。

## 5. 你的独立功能

首个个人功能选择“可信知识卡”：让用户知道每张 AI 卡片依据哪段原文、模型有多确定，以及为什么某些卡片需要人工确认。

详细设计和待选择问题见 `docs/TRUSTED_CARDS_DESIGN.md`。这个功能完成后，才把它作为个人核心贡献写入简历。

## 7. 三分钟项目讲解模板

不要逐字背诵，只按结构组织：

1. **问题**：普通笔记保存了内容，但难以把长对话变成可复习、可关联的知识。
2. **基础**：选择 NoteGen 作为编辑器和 Tauri 桌面基础，而不是重写通用笔记能力。
3. **改造**：围绕 CardMind 增加知识卡片、图谱、ChatGPT 导入和结构化知识摄取。
4. **核心链路**：选择一条调用链从输入讲到 SQLite。
5. **工程难点**：分块完整性、模型 JSON 不稳定、幂等、来源追踪和工具权限。
6. **当前不足**：两条知识模型还未统一，生产数据闭环需要继续验证。
7. **下一步**：可信知识卡和知识数据模型统一。

9. 如果模型生成非法 JSON，系统如何恢复？
10. 你亲自做出的一个设计选择是什么，放弃了什么方案？

## 9. Git 证据要求

当前本地历史能看到上游提交，但 CardMind 改造仍主要集中在未提交工作区。公开前需要：

- 先做完整备份并确认所有改动来源。
- 按真实功能拆分提交，不伪造日期和作者。
- 每个提交只解决一个主题，并带对应测试或验证记录。
- 在 README 保留 NoteGen 来源和 GPL-3.0 许可说明。
- 不把上游已有 Agent 框架描述为个人从零实现。

完成后，面试证据应形成闭环：设计说明 -> 代码提交 -> 测试结果 -> 运行截图 -> 口头讲解。
